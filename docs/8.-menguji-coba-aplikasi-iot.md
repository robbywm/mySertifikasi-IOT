Aspek kritis unit ini adalah kecermatan dalam menguji usability dari UI serta menguji UX pada tampilan dan alur kerja aplikasi.

## 1. Landasan Teori

Setelah perangkat keras lulus QC pada Bab 7, giliran aplikasinya yang diuji. Aplikasi pada pelatihan ini adalah dashboard Blynk, baik yang dibuka lewat browser maupun lewat smartphone.

### 1.1. Tiga jenis pengujian

SKKNI membedakan tiga pengujian, dan ketiganya sering tertukar.

| Pengujian | Pertanyaan yang dijawab | Cara menguji | Contoh |
| --- | --- | --- | --- |
| Kesesuaian UI (*User Interface*) | Apakah tampilan sama dengan desainnya? | Membandingkan dashboard dengan tabel spesifikasi | Gauge suhu terhubung ke V0 dan bersatuan °C |
| Usability test | Apakah setiap komponen dan fitur berfungsi? | Mengoperasikan setiap widget satu per satu | Switch V3 benar-benar menyalakan LED |
| UX test (*User Experience*) | Apakah pengguna dapat menyelesaikan tugasnya dengan mudah? | Meminta orang lain mengerjakan tugas tanpa dibantu, lalu mengamatinya | Rekan Anda menemukan suhu ruangan dalam 10 detik |

UI adalah sarana pengguna untuk berinteraksi dengan aplikasi. Usability test memeriksa fungsi kerja komponen dan fiturnya, sedangkan UX test memeriksa tampilan dan alur kerja aplikasi dari sudut pandang pengguna.

### 1.2. Firmware terintegrasi

Dashboard baru dapat diuji secara utuh apabila perangkat mengirim seluruh data sekaligus. Karena itu, bab ini dimulai dengan memasang firmware versi 0.2.0 yang menggabungkan pembacaan DHT22, BMP280, potensiometer, dan tombol, serta pengendalian LED, di dalam kerangka Blynk Edgent. Firmware ini dikirim lewat Blynk.Air seperti pada Bab 6.

### 1.3. Kinerja jaringan

Aplikasi IoT yang tampilannya baik akan tetap terasa buruk bila datanya terlambat, sehingga dua hal berikut ikut diperiksa:

* **Sinkronisasi dua arah.** Perintah dari dashboard sampai ke perangkat, dan perubahan di perangkat tampil di dashboard.
* **Latency.** Jeda antara perintah dikirim dan hasilnya terlihat. Nilai *ping* ke server Blynk dipakai sebagai ukurannya.

| Ping | Penilaian |
| --- | --- |
| Kurang dari 100 ms | Sangat baik |
| 100 sampai 300 ms | Cukup |
| Lebih dari 300 ms | Buruk, dashboard mulai terasa lambat |

#### 2. Periksa versinya

Versi firmware ini adalah 0.2.0. Angka tengahnya dinaikkan karena firmware ini menambah banyak fitur, sedangkan patch pada Bab 6 hanya menaikkan angka terakhir.

Pada baris ke-5 berkas `.ino`, pastikan `BLYNK_FIRMWARE_VERSION` bernilai `"0.2.0"`.

```cpp
#define BLYNK_TEMPLATE_ID "TMPLxxxxxx"
#define BLYNK_TEMPLATE_NAME "MySertifikasi"

// VERSI PEMBARUAN MAYOR (INTEGRASI SISTEM)
#define BLYNK_FIRMWARE_VERSION        "0.2.0"
#define BLYNK_PRINT Serial
#define APP_DEBUG
#define USE_KASGARIOT_SHIELD

#include "BlynkEdgent.h"
#include <Wire.h>
#include <Adafruit_Sensor.h>
#include <Adafruit_BMP280.h>
#include <DHT.h>

// --- Definisi Pin KasgarIoT Shield R1 ---
#define PIN_LED D4       
#define PIN_TOMBOL D3   
#define PIN_ANALOG A0    
#define DHTPIN D5       
#define DHTTYPE DHT22

DHT dht(DHTPIN, DHTTYPE);
Adafruit_BMP280 bmp;
BlynkTimer timer;

int statusTombolTerakhir = HIGH;
bool bmpSiap = false;

BLYNK_WRITE(V3) {
  int statusSwitch = param.asInt();
  // Inversi (!) karena rangkaian D4 bersifat Active LOW
  digitalWrite(PIN_LED, !statusSwitch); 
}

// 1. Fungsi Cepat: Mengecek input Tombol (Dieksekusi tiap 100 milidetik)
void cekTombol() {
  int statusTombolSekarang = digitalRead(PIN_TOMBOL);
  
  if (statusTombolSekarang != statusTombolTerakhir) {
    delay(50); 
    int statusValid = digitalRead(PIN_TOMBOL);
    
    if (statusValid == statusTombolSekarang) {
      int nilaiKirim = !statusValid; 
      Blynk.virtualWrite(V4, nilaiKirim);
      statusTombolTerakhir = statusValid; 
      
      if(nilaiKirim == 1){
        Serial.println("Tombol Fisik Ditekan!");
      }
    }
  }
}

// 2. Fungsi Lambat: Pengiriman Data Sensor (Dieksekusi tiap 2 Detik)
void kirimDataSensor() {
  int nilaiPot = analogRead(PIN_ANALOG);
  Blynk.virtualWrite(V5, nilaiPot);

  // Baca DHT22 (V0 Suhu, V1 Kelembapan)
  float kelembapan = dht.readHumidity();
  float suhu = dht.readTemperature();
  if (!isnan(kelembapan) && !isnan(suhu)) {
    Blynk.virtualWrite(V0, suhu);
    Blynk.virtualWrite(V1, kelembapan);
  }

  // Baca BMP280 (V2 Tekanan Udara)
  if (bmpSiap) {
    Blynk.virtualWrite(V2, bmp.readPressure() / 100.0F);
  }
  
  Serial.println("Data Sensor (DHT, BMP, Potensiometer) Berhasil Dikirim.");
}

void setup() {
  Serial.begin(115200);
  delay(100);
  pinMode(PIN_LED, OUTPUT);
  digitalWrite(PIN_LED, HIGH);
  pinMode(PIN_TOMBOL, INPUT_PULLUP);

  dht.begin();
  // Alamat I2C BMP280 adalah 0x76 atau 0x77, tergantung pin SDO pada modul
  bmpSiap = bmp.begin(0x76) || bmp.begin(0x77);
  if (!bmpSiap) {
    Serial.println("PERINGATAN: Gagal menemukan sensor BMP280!");
  }

  BlynkEdgent.begin();
  timer.setInterval(100L, cekTombol);
  timer.setInterval(2000L, kirimDataSensor);
}

void loop() {
  BlynkEdgent.run();
  timer.run();
}
```

**Mengukur latency**

Hubungkan perangkat ke laptop, buka Serial Monitor pada 115200 baud, lalu tekan tombol RESET pada board. Setelah perangkat terhubung, catat angka pada baris `Ready (ping: ...ms)`. Ulangi tiga kali dan hitung rata-ratanya.

## 6. Langkah Kerja 5: UX Test

UX test dilakukan oleh orang lain, sebab Anda sudah terlalu mengenal dashboard buatan sendiri. Minta seorang rekan yang belum pernah melihat dashboard Anda untuk mengerjakan tugas berikut **tanpa petunjuk**. Ukur waktunya dengan stopwatch dan catat pada bagian mana ia ragu atau keliru.

| No | Tugas untuk pengguna | Sasaran waktu | Waktu aktual | Berhasil tanpa bantuan? | Pengamatan |
| --- | --- | --- | --- | --- | --- |
| 1 | "Berapa suhu ruangan saat ini?" | 10 detik | | | |
| 2 | "Nyalakan lampu indikator pada perangkat." | 10 detik | | | |
| 3 | "Apakah tombol pada perangkat sedang ditekan?" | 15 detik | | | |
| 4 | "Bagaimana perubahan suhu selama 15 menit terakhir?" | 20 detik | | | |
| 5 | Ulangi tugas 1 dan 2 lewat smartphone | 20 detik | | | |

Setelah itu, ajukan tiga pertanyaan kepada rekan Anda dan tuliskan jawabannya:

1. Bagian mana yang paling membingungkan?
2. Informasi apa yang ia harapkan ada tetapi tidak ditemukan?
3. Dari skala 1 sampai 5, seberapa mudah dashboard ini dipakai?

Di smartphone, perhatikan juga apakah tombol cukup besar untuk jari dan apakah seluruh nilai terbaca tanpa memperbesar layar.

{% hint style="success" %}
**Tantangan lanjutan.**

* Tambahkan `BLYNK_CONNECTED() { Blynk.syncVirtual(V3); }` pada firmware agar LED kembali ke status terakhir Switch setelah perangkat restart, lalu kirim sebagai versi 0.2.1 lewat OTA dan uji ulang butir yang terkait.
* Lakukan UX test dengan tiga orang, lalu hitung tingkat keberhasilan dan rata-rata waktu setiap tugas.
* Ukur latency ujung ke ujung dengan merekam video layar dan LED secara bersamaan, lalu hitung selisih waktunya per bingkai.
* Kirim nilai RSSI dan waktu hidup perangkat (*uptime*) ke datastream baru, lalu tampilkan di dashboard sebagai alat pantau kesehatan perangkat.
