## 1. Landasan Teori

Perangkat yang sudah terpasang belum dapat melakukan apa pun sebelum diisi *firmware*, yaitu program yang tersimpan di memori mikrokontroler. Pada bab ini Anda menulis firmware pendek untuk mengakses setiap komponen pada shield, lalu membandingkan perilakunya dengan datasheet.

### 1.1. Arduino IDE

Arduino IDE (*Integrated Development Environment*) dipakai untuk menulis program dengan sintaks C++, meng-compile, dan meng-upload hasilnya ke memori flash mikrokontroler.

### 1.2. Struktur dasar program

Program pada Arduino IDE disebut *sketch*, dan setiap sketch wajib memiliki dua fungsi berikut.

* `void setup()` dijalankan satu kali ketika perangkat menyala atau di-reset. Fungsi ini biasanya berisi pengaturan kecepatan serial dan mode pin (`INPUT` atau `OUTPUT`).
* `void loop()` dijalankan berulang-ulang selama perangkat mendapat daya. Pembacaan sensor dan pengendalian aktuator ditulis di sini.

### 1.3. Komunikasi serial dan chip CH340

Chip CH340 pada Wemos mengubah sinyal USB dari laptop menjadi sinyal serial (TX/RX) yang dipahami ESP8266. Jalur yang sama dipakai untuk dua keperluan: meng-upload program dan menampilkan data ke Serial Monitor saat *debugging*.

{% hint style="info" %}
**Untuk pemula.** Angka pada `Serial.begin(9600)` adalah *baud rate*, yaitu kecepatan kirim data. Angka di pojok kanan bawah Serial Monitor harus sama. Bila berbeda, yang tampil hanya karakter acak.
{% endhint %}

### 1.4. Protokol komunikasi dengan komponen

SKKNI menyebut beberapa protokol standar untuk komunikasi antara mikrokontroler dan komponen, dan empat di antaranya dipakai pada shield ini.

| Protokol | Dipakai oleh | Ciri |
| --- | --- | --- |
| Digital in/out | LED, tombol | Hanya dua nilai, HIGH atau LOW |
| Analog in (ADC) | Potensiometer | Tegangan diubah menjadi angka 0 sampai 1023 |
| Digital satu kabel | DHT22 | Data suhu dan kelembapan dikirim bergantian lewat satu pin, dengan protokol khusus DHT |
| I2C | BMP280 | Dua kabel (SDA dan SCL), setiap komponen memiliki alamat |

### 1.5. Library

*Library* adalah kumpulan kode siap pakai untuk berkomunikasi dengan komponen tertentu. Dengan library, Anda cukup memanggil `dht.readTemperature()` tanpa perlu menulis sendiri protokol DHT22. Instal dua library berikut melalui **Sketch > Include Library > Manage Libraries**.

| Library | Untuk komponen | Catatan |
| --- | --- | --- |
| DHT sensor library by Adafruit | DHT22 | Jika diminta, setujui instalasi *Adafruit Unified Sensor* |
| Adafruit BMP280 Library | BMP280 | Jika diminta, setujui instalasi dependensinya |

### Pengujian 1: Output Digital (LED)

LED status terhubung ke pin D4 dengan logika Active LOW, sehingga LED menyala ketika pin diberi LOW dan padam ketika diberi HIGH. Rangkaian seperti ini dipilih karena pin D4 (GPIO2) harus berada pada kondisi HIGH ketika ESP8266 mulai menyala.

Program: [`1.Pengujian_LED`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/1.Pengujian_LED)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
int ledPin = D4;
void setup() {
  Serial.begin(9600);
  Serial.println("Pengujian LED D4 Kasgar IoTShield Dimulai...");
  pinMode(ledPin, OUTPUT);
}
void loop() {
  digitalWrite(ledPin, LOW); 
  Serial.println("LED Menyala");
  delay(1000);
  digitalWrite(ledPin, HIGH);
  Serial.println("LED Padam");
  delay(1000);
}
```

### Pengujian 2: Input Digital (Tombol)

Tombol USER terhubung ke pin D3. Saat ditekan, tombol itu menghubungkan pin ke GND sehingga terbaca 0, sedangkan saat dilepas pin ditahan pada nilai 1 oleh resistor *pull-up* internal mikrokontroler, yang diaktifkan oleh mode `INPUT_PULLUP` pada program.

Program: [`2.Pengujian_Switch`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/2.Pengujian_Switch)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
int btnPin = D3;

void setup() {
  Serial.begin(9600);
  Serial.println("Pengujian User Button Dimulai...");
  pinMode(btnPin, INPUT_PULLUP);
}

void loop() {
  int statusBtn = digitalRead(btnPin);

  Serial.print("Status User Button (D3): ");
  Serial.println(statusBtn); // Akan bernilai 0 jika ditekan, 1 jika dilepas

  delay(500);
}
```

### Pengujian 3: Integrasi Tombol dan LED

Pengujian ini menggabungkan dua program sebelumnya, sehingga LED D4 hanya akan menyala selama tombol D3 ditekan. Kedua komponen sama-sama Active LOW, sehingga pin LED diberi LOW ketika tombol terbaca LOW.

Program: [`3.Pengujian_Switch_LED`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/3.Pengujian_Switch_LED)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
int btnPin = D3;
int ledPin = D4;

void setup() {
  Serial.begin(9600);
  Serial.println("Pengujian Interaksi Tombol dan LED Dimulai...");
  
  pinMode(btnPin, INPUT_PULLUP); 
  pinMode(ledPin, OUTPUT);   
}

void loop() {
  int statusBtn = digitalRead(btnPin);

  if (statusBtn == LOW) {
    digitalWrite(ledPin, LOW); 
    Serial.println("Tombol Ditekan -> LED Menyala");
  } else {
    digitalWrite(ledPin, HIGH);
    Serial.println("Tombol Dilepas -> LED Padam");
  }
   // Sedikit jeda (debounce) agar pembacaan stabil
  delay(100);
}
```

### Pengujian 4: Sensor DHT22 (Suhu dan Kelembapan)

Sensor DHT22 terhubung ke pin **D5**. Datasheet sensor ini mensyaratkan jeda minimal 2 detik antarpembacaan, dan itulah alasan adanya `delay(2000)` di awal `loop()`.

Program: [`4.Pengujian_DHT22`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/4.Pengujian_DHT22)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
#include "DHT.h"
#define DHTPIN D5       // Pin D5 pada Wemos D1 R2
#define DHTTYPE DHT22   // Tipe sensor DHT22

DHT dht(DHTPIN, DHTTYPE);

void setup() {
  Serial.begin(9600);
  Serial.println("Pengujian Sensor DHT22 Dimulai...");
  dht.begin();
}

void loop() {
  delay(2000);
  
  float h = dht.readHumidity();
  float t = dht.readTemperature();

  // Validasi apakah pembacaan berhasil
  if (isnan(h) || isnan(t)) {
    Serial.println("Gagal membaca dari sensor DHT!");
    return;
  }
  Serial.print("Kelembapan: ");
  Serial.print(h);
  Serial.print(" %\t");
  Serial.print("Suhu: ");
  Serial.print(t);
  Serial.println(" *C");
}
```

### Pengujian 6: Sensor I2C (BMP280)

Sensor BMP280 terhubung ke jalur I2C (SCL di D1, SDA di D2) dan membaca suhu, tekanan udara, serta perkiraan ketinggian. Alamat I2C modul ini adalah 0x76 atau 0x77, bergantung pada rangkaian modulnya, sehingga program mencoba kedua alamat itu secara berurutan.

Program: [`6.Pengujian_BMP280`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/6.Pengujian_BMP280)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
#include <Wire.h>
#include <Adafruit_Sensor.h>
#include <Adafruit_BMP280.h>

Adafruit_BMP280 bmp; 

void setup() {
  Serial.begin(9600);
  Serial.println(F("Pengujian Sensor BMP280 Dimulai..."));

  // Alamat I2C BMP280 adalah 0x76 atau 0x77, tergantung pin SDO pada modul
  if (!bmp.begin(0x76) && !bmp.begin(0x77)) {
    Serial.println(F("Gagal menemukan sensor BMP280!"));
    Serial.println(F("Periksa pemasangan modul pada port I2C."));
    while (1); 
  }

  Serial.println(F("Sensor BMP280 Berhasil Diinisialisasi!"));

  // Pengaturan sampling standar untuk hasil yang stabil
  bmp.setSampling(Adafruit_BMP280::MODE_NORMAL,     
                  Adafruit_BMP280::SAMPLING_X2,     
                  Adafruit_BMP280::SAMPLING_X16,    
                  Adafruit_BMP280::FILTER_X16,      
                  Adafruit_BMP280::STANDBY_MS_500); 
}

void loop() {
  // 1. Membaca Suhu dalam derajat Celsius (*C)
  float suhu = bmp.readTemperature();
  
  // 2. Membaca Tekanan Udara (Pascal dibagi 100 menjadi hPa)
  float tekanan = bmp.readPressure() / 100.0F;

  // 3. Membaca Perkiraan Ketinggian (Meter)
  // 1013.25 adalah tekanan udara standar di permukaan laut (hPa)
  float ketinggian = bmp.readAltitude(1013.25);

  // Menampilkan hasil pembacaan ke Serial Monitor
  Serial.print(F("Suhu: "));
  Serial.print(suhu);
  Serial.print(F(" *C \t| "));
  
  Serial.print(F("Tekanan: "));
  Serial.print(tekanan);
  Serial.print(F(" hPa \t| "));
  
  Serial.print(F("Ketinggian: "));
  Serial.print(ketinggian);
  Serial.println(F(" m"));

  delay(2000);
}
```

### Pengujian 7: Output Digital Majemuk (LED RGB)

LED RGB pada shield memakai logika Active HIGH: merah di D7, biru di D6, dan hijau di D8. Pin D8 (GPIO15) harus berada pada kondisi LOW ketika ESP8266 mulai menyala, sehingga LED di pin itu memang harus padam pada kondisi LOW.

Program: [`7.Pengujian_RGB`](https://github.com/robbywm/mySertifikasi-IOT/tree/main/7.Pengujian_RGB)

Kode lengkap juga tersedia di GitHub lewat tautan di atas.

```cpp
// Definisi Pin sesuai routing KasgarIoT R1
int pinMerah = D7;
int pinBiru  = D6;
int pinHijau = D8;

void setup() {
  Serial.begin(9600);
  Serial.println("Pengujian RGB LED Dimulai...");
  pinMode(pinMerah, OUTPUT);
  pinMode(pinBiru, OUTPUT);
  pinMode(pinHijau, OUTPUT);
}

void loop() {
  // 1. Nyalakan warna Merah saja
  digitalWrite(pinMerah, HIGH);
  digitalWrite(pinBiru, LOW);
  digitalWrite(pinHijau, LOW);
  Serial.println("Warna RGB: MERAH");
  delay(1000);

  // 2. Nyalakan warna Hijau saja 
  digitalWrite(pinMerah, LOW);
  digitalWrite(pinBiru, LOW);
  digitalWrite(pinHijau, HIGH);
  Serial.println("Warna RGB: HIJAU");
  delay(1000);

  // 3. Nyalakan warna Biru saja 
  digitalWrite(pinMerah, LOW);
  digitalWrite(pinBiru, HIGH);
  digitalWrite(pinHijau, LOW);
  Serial.println("Warna RGB: BIRU");
  delay(1000);
}
```

| Gejala | Yang perlu diperiksa |
| --- | --- |
| "Gagal membaca dari sensor DHT!" muncul terus | Pin pada program harus D5, shield terpasang rapat, library DHT sudah terinstal |
| "Gagal menemukan sensor BMP280!" | Shield terpasang rapat, pin D1 dan D2 tidak bengkok |
| Nilai potensiometer melompat-lompat | Kontak potensiometer kotor atau aus, ukur tegangan A0 dengan multimeter |
| Salah satu warna LED RGB tidak menyala | Tukar urutan uji untuk memastikan bukan kesalahan program, lalu ukur tegangan pin saat HIGH |
| Suhu DHT22 terpaut jauh dari termometer pembanding | Sensor terkena panas dari chip atau tangan, ulangi setelah perangkat didiamkan 5 menit |

## 5. Cek Pemahaman

1. Mengapa `digitalWrite(D4, LOW)` menyalakan LED status?
2. Apa fungsi `INPUT_PULLUP` pada pengujian tombol?
3. Mengapa DHT22 tidak boleh dibaca lebih sering dari 2 detik sekali?
4. Bagaimana mikrokontroler membedakan dua sensor yang terhubung ke jalur I2C yang sama?
5. Kapan sebuah komponen dinyatakan tidak sesuai dengan datasheet?

{% hint style="success" %}
**Tantangan lanjutan.**

* Ubah program Pengujian 7 sehingga kecerahan LED merah mengikuti putaran potensiometer dengan `analogWrite()` (PWM).
* Ganti `delay()` pada program Pengujian 3 dengan pewaktuan `millis()`, sehingga program tetap dapat mengerjakan tugas lain sambil menunggu.
* Tulis satu firmware yang membaca seluruh sensor dan menampilkannya dalam satu baris berformat CSV, lalu buat grafiknya dengan **Tools > Serial Plotter**.
* Ukur dan catat selisih suhu DHT22 dengan BMP280 selama 10 menit. Jelaskan sumber selisihnya berdasarkan datasheet.
